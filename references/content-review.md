# 内容审查清单

渲染前先读 `content.md`，输出一份 `REVIEW.md`，用户确认后再出图。

**边界：报告问题、给出建议，但不擅自改写用户的文案。** 用户对着 REVIEW.md 自己改，或明确说"按你的建议改"我才动手。

分两层：

| 层 | 谁做 | 查什么 |
|---|---|---|
| 客观 | `--dry-run` | 渲染高度溢出、素材文件缺失、封面字数超限 |
| 主观 | 我读 md | 标题钩子、信息密度、卡片顺序、结构完整性 |

**先跑 `--dry-run` 再写 REVIEW.md** —— 客观数字能佐证主观判断（"这张卡我觉得信息过载" + "实测溢出 223px" 比单说前者有说服力得多）。

```bash
python scripts/render_xhs.py content.md --dry-run
```

## 主观维度

### 1. 封面标题钩子

封面决定点击率，是最该较真的一张。

弱标题的特征：
- 只描述话题，不给收益（"关于时间管理的思考"）
- 没有具体数字
- 没有人群指向，谁都能划走
- 形容词堆砌代替具体信息（"超好用的神器合集"）

强标题通常至少占两条：**具体数字** / **明确人群** / **可感知的收益或代价** / **反直觉的断言**。

模板硬约束：`title` ≤ 15 字最佳，超 30 字会掉到最小字号；`subtitle` ≤ 15 字，**无自动缩放**，超了直接溢出。

### 2. 单卡信息密度

一张卡一个观点。判断过载看三个信号：

- bullet 超过 5 条
- bullet 平均字数超过 30
- 一张卡里出现两个并列的 `#` 一级标题

出现两条以上就建议拆卡。**拆卡几乎没有代价** —— 小红书图文本来就是多图轮播，多一张比挤成一张好。

反过来也要看：一张卡只有一句话、大片留白，说明该合并。

### 3. 卡片顺序

- **最强的观点是否在前面。** 用户翻到第 3 张的概率远低于第 2 张，把压轴内容放最后是浪费。
- 是否有递进或并列的清晰逻辑，还是随手排的。
- 是否存在"第 4 张才交代前提"这种倒置。

### 4. 结构完整性

- 有没有结尾卡（行动号召 / 总结 / 互动提问）。缺结尾卡是最常见的问题。
- 标签（`#xxx`）是否存在，5-10 个为宜，写在最后一张卡末尾。
- 首卡是否承接了封面标题的承诺 —— 封面说"5 个工具"，正文只有 3 个就是失信。

### 5. 素材是否在做事

素材要**辅助表意**，不是装饰填空。

对每个引用的 SVG 问一句：去掉它，这张卡的信息量会不会下降？不会就删掉。流程图、对比图、结构图值得留；纯图标装饰通常不值得。

## REVIEW.md 输出格式

逐卡列「现状 → 建议 → 原因」，问题卡在前，没问题的卡一行带过。

```markdown
# 内容审查：content.md

**客观体检**（`--dry-run`）
- 卡片 3 渲染高度 1663px / 1440px，溢出 223px
- 素材 materials/flow.svg 找不到

---

## 封面 ⚠️

- 现状：`5个效率神器` / `让工作效率翻倍`
- 建议：`这5个工具让我每天少加班1小时`
- 原因：原标题有数字但无具体收益，"效率翻倍"是形容词不是可感知结果

## 卡片 3 ❌ 信息过载

- 现状：6 条 bullet，平均 34 字，实测溢出 223px
- 建议：按"必装插件"与"进阶用法"拆成卡片 3 / 卡片 4
- 原因：超出画布会被裁切；6 条并列信息读者记不住

## 卡片 5 ⚠️ 素材

- 现状：`![](materials/badge.svg)` 是个纯装饰对勾
- 建议：删除，或换成三个工具的能力对比图
- 原因：去掉不损失信息量，占了 380px 高度

## 卡片 1、2、4 ✅

---

## 整体

- ❌ 缺结尾行动卡。建议加第 6 张：一句话总结 + "你在用哪个？评论区聊聊"
- ⚠️ 无标签。建议末卡加 `#效率工具 #数字生产力 #Mac神器` 等 5-8 个
- ✅ 卡片顺序合理，最强的 Notion 放在首位
```

## 什么时候不该报

避免把个人审美当问题报：

- 用户的语气偏好（活泼 / 克制）不是问题
- emoji 用得多少是风格选择，除非多到干扰阅读
- 内容的观点立场不评判
- 已经明确说过"就这么写"的地方不要反复提
