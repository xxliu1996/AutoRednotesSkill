# 封面设计

**封面决定点击率，其余 N 张决定完读率。** 花在封面上的时间应该多于任何一张正文卡。

---

## 三条硬约束（几何）

画布 1080×1440。

| 区域 | 尺寸 | 说明 |
|---|---|---|
| **底部 App UI 遮挡带** | 底部约 **150px** | 信息流里 App 会压上笔记标题和作者名。**核心信息绝不能放这里** |
| **绝对安全区** | 居中的 **1080×1080** | 个人主页可能按 1:1 裁切，主标题必须落在这个正方形内 |
| 四周内缩 | 40–60px | 防止贴边显局促 |

渲染器已经在 `.cover-inner` 底部预留了 `UI_SAFE_BOTTOM = 150`，
所以副标题不会掉进遮挡带。但**封面正文如果太长仍会溢出** ——
`--dry-run` 会报「封面正文溢出 N px」，必须清零才能出图。

## 标题：先把字放大

小红书主标题的通行量级是 **80–120pt Bold**，爆款封面往往更大。
渲染器按「最长的一行」自动定字号：

| 最长行字数 | 字号 | 观感 |
|---|---|---|
| ≤ 4 | 0.20 × 宽 = **216px** | 超大，封面主视觉 |
| ≤ 6 | 0.17 × 宽 = 183px | 大 |
| ≤ 10 | 0.13 × 宽 = 140px | 中 |
| ≤ 18 | 0.095 × 宽 = 102px | 小 |
| > 18 | 更小 | 已经不该出现在封面上 |

**所以标题越短，字越大，冲击力越强。** 这不是风格偏好，是数学。

### 用 `<br>` 把长标题拆成短行

字号按最长的一行算，**主动断行反而能把字放大**：

```yaml
title: "Vibe Coding 的 5 个技巧"      # 单行 13 字 → 102px，弱
title: "Vibe Coding<br>5个技巧"       # 最长行 11 字 → 140px
title: "提效秘籍<br>5个技巧"           # 最长行 4 字 → 216px，强
```

小红书封面最常见的就是这种**两行短句**结构。

### 关键词高亮

把最关键的那个词抠出来，让人一眼先看到它：

```yaml
title: "<span class='hl'>5个技巧</span><br>让AI听话"        # 对比色文字
title: "让AI听话的<br><span class='hl-box'>5个技巧</span>"   # 强调色块抠字
```

`hl` = 强调色文字；`hl-box` = 强调色块 + 反白字。**一个封面只高亮一处**。

> 实现上的坑：`.cover-title` 用 `background-clip:text` 做渐变裁切，
> **子元素会继承那份透明**。所以高亮类必须显式写回 `-webkit-text-fill-color`，
> 否则整段字消失且无报错。

## 内容：给眼睛三个落点，不是一个

只有「emoji + 标题 + 副标题」的封面必然单调 —— 那是三行字加一片空。

封面正文（frontmatter 与第一个 `# ` 之间）走完整管线，组件和配图都能用。
但**空间只够一样**：

| 想放 | 怎么放 |
|---|---|
| 并列要点 | `grid grid-2 palette-solid` 四个彩色方块 |
| 一张主视觉 | `![size=lg align=center]` |
| 数字/成绩 | `stats` |
| 一句钩子 | `highlight` |

**宫格和配图二选一** —— 两样都塞会挤，`--dry-run` 会报警。
既然是二选一，就**默认出两版让用户挑**（`<!-- or -->` 分隔）。

### 留白 30%

不要把封面填满。标题足够大 + 一组视觉元素 + 30% 留白，比塞满更抓人。

## 配图：切题比好看重要

封面配图最容易犯的错是**拿一个泛泛的图标充数** —— 灯泡代表"点子"、
齿轮代表"技术"、放大镜代表"搜索"。这些图谁的封面都能用，也就等于没用。

判据：**这张图能不能只属于这篇笔记？**

| ❌ 泛泛 | ✅ 切题 |
|---|---|
| 灯泡（点子） | 内容里那个具体的东西 |
| 齿轮（技术） | 那个工具的界面/形态 |
| 放大镜（搜索） | 被搜的对象本身 |

搜不到切题的就**别放图，改用宫格**。四个彩色方块写四个关键词，
信息量和冲击力都比一个泛图标强。

深色主题还要过亮度关（见 `image-sourcing.md`）：**可见亮度 >90**，
否则黑线稿会直接消失。

## 自检

```bash
python scripts/render_xhs.py content.md -t <theme> --dry-run
```

封面相关的检查：

- **封面正文溢出** —— 末尾会被裁掉并被副标题压住，必须清零
- **标题孤字** —— 末行只剩一两个字
- **封面硬塞** —— 栅格和配图同时出现
- 标题最长行 / 副标题字数

脚本量不出、要自己看的：

- [ ] 眯眼看 3 秒，能不能说出这篇讲什么
- [ ] 标题是不是**封面上最大的东西**
- [ ] 配图换成任何一张同类图，封面会不会毫无变化（会 → 说明图没在做事）
- [ ] 底部 150px 里有没有放重要信息
- [ ] 主标题是否完整落在居中的 1080×1080 内

## 常见错误

**标题太长导致字小。** 13 字的标题只能拿到 102px，4 字能拿到 216px。
砍字比调样式有效得多。

**副标题重复标题的信息。** 副标题应该补充新信息（人群、场景、收益），
不是把标题换个说法再讲一遍。

**用了通用图标。** 见上。

**深底浅字。** 通行建议是高对比（白底黑字、黄底黑字）。深色封面不是不能做，
但要靠强调色块和大字撑起对比 —— 光靠深底 + 浅灰字必然弱。
