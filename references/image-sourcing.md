# 自动配图

**机器负责抓，我负责挑和摆。**

图片切不切题是判断题：搜「历史」会返回古籍、博物馆、老照片、罗马废墟，
相关度排第一的未必配得上这段文案。所以脚本只做检索和下载，选哪张、放哪里、多大，
我看图决定。

---

## 流程

```bash
# 1. 抓候选（关键词用英文，命中率明显更高）
python scripts/fetch_images.py "tank military history" -o ./assets -n 6

# 2. 我 Read 联系表 assets/candidates/<slug>-sheet.png —— 一张图看全部，带编号
# 3. 选中的移到素材目录，其余删掉
# 4. 在 content.md 里引用，尺寸和位置由我按版式定
```

联系表是为了省成本：6 张候选逐一 Read 要 6 次，拼成一张只要 1 次。

`candidates/MANIFEST.md` 记录每张图的作者、标签、原始页面 —— 出处要留痕，
以后想换图或核对授权都用得上。

---

## 关键词怎么给

从卡片内容里提炼**具体名词**，不要用抽象概念：

| 卡片讲的 | ❌ 别搜 | ✅ 搜这个 |
|---|---|---|
| 研究历史事件影响市场 | history / 历史 | `tank military` `stock chart crash` |
| 观察富人的消费 | rich people | `bull market finance` `luxury watch` |
| 政府规划文件 | government policy | `document stamp official` |
| AI 提升效率 | artificial intelligence | `robot hand keyboard` |

抽象词返回的多是概念插画和图标，很难跟具体文案对上。**具体的物**更容易配。

中文可以搜（加 `--lang zh`），但图库的标签体系以英文为主，命中率低不少。
我负责把中文文案翻成检索词，这一步不该甩给用户。

## 参数选择

| 想要 | 参数 |
|---|---|
| 深色主题配图（首选） | `--type vector --min-width 700` —— 真透明 PNG |
| 实拍照片 | `--type photo` |
| 插画 / 卡通 | `--type illustration` |
| 满宽 hero 图 | `--orientation horizontal --min-width 1600` |
| 竖构图配文字 | `--orientation vertical` |

`--min-width` 默认 1200，够 `size=xl`（560px 显示宽 × dpr 2）用。
要做 `hero` 通栏提到 1600 以上 —— **但那样就搜不到 vector**（最大 1280px），
需要透明通道时把它调到 700-900。

## 先看本地素材，再去图库搜

**本地用户提供的素材包永远排第一**，Pixabay 是没有本地素材时的兜底，不是默认选项。

判断依据很直接：用户样图里的插图/图标是一套统一风格（同一个画师、同一个图库买的
同系列），图库临时搜到的东西风格必然杂——搜十次十种画风，跟样图的贴合度天然低于
用户自己攒的素材包。

流程：

```bash
ls <项目目录>/materials/icons/    # 或用户告知的素材目录
# 先看这里有没有语义匹配的，命名通常是英文关键词（book.png / robot.png / idea.png）
```

有匹配的直接用；没有才 `fetch_images.py` 搜 Pixabay。

**背景纹理同理，也优先用真实素材而不是 CSS 模拟。** 见 `style-extraction.md`
「背景纹理：真实素材优先于 CSS 模拟」一节——这条踩过一次真实的坑：第一版给
`kraft-marker` 用径向渐变模拟牛皮纸颗粒感，跟真实纹理图一比，没有纤维感，
色板距离和观感都明显更差；换成真实素材（压缩后 base64 内嵌进 `bg_card`）才真正对上。

## 亮度：深色主题挑图的第一道关

`fetch_images.py` 现在会报每张候选「可见部分的平均亮度」（忽略透明像素）：

```
[1] robot-tools-wrench-1.png  1280x1280  by X  亮度 114.5
[2] robot-tools-wrench-2.png  1280x640   by Y  亮度  22.1 ← 深色主题上会糊
```

**图库的 vector 素材大量是黑色线稿**（本来就是给浅底设计的）。放在深色主题上
直接消失，而联系表看着"有内容"—— 挑完出图才发现是一片空。

判据：**深色主题要 >90，浅色主题要 <170。**

### 但要看它最终落在什么底色上

图标如果放进 `palette-solid` 的彩色面板里，它压的是**饱和中间调**，不是页面底色。
这时白色/浅色图标最稳（在蓝、红、绿面板上都读得清），亮度 200+ 那些
"浅色主题上会糊"的反而是首选。

**先想清楚图落在哪一层，再看亮度。**

## 图源类型：讲解性内容用卡通，实物用照片

`kraft-marker` 的样图逐张看下来是按内容类型分图源的，不是统一用一种风格：

| 配图讲的是 | 用什么 |
|---|---|
| 概念、原理、人在做什么 | 卡通/矢量插画（`--type illustration` 或 `--type vector`） |
| 具体的产品、建筑、玩具实物 | 写实照片（`--type photo`） |

样图从不用写实照片表现抽象概念，只用它表现"这个东西长什么样"——挑图前先判断
这张卡讲的是哪一种。

## 摆放判断

拿到图之后，尺寸和位置**跟着版式走，不是跟着图走**：

| 图的角色 | 怎么放 |
|---|---|
| 这张卡的主视觉 | `![size=xl align=center]` 或 `hero` 通栏 |
| 配合一段文字说明 | `![size=lg align=left]` 让正文绕排 |
| 只是点缀 | 删掉 —— 见下 |

**去掉这张图，卡片的信息量会不会下降？不会就别放。**
纯装饰图在小红书卡片上是负资产：占掉正文空间，还稀释重点。

深色主题上如果拿到的是**去背 PNG**（透明通道），直接放，不要加相框 ——
剪影浮在满版深色底上是最省事也最好看的组合。

## 透明通道：用 `--type vector`

**这是深色主题下最关键的一个参数。**

| type | 返回格式 | 透明 |
|---|---|---|
| `photo` | JPEG | ❌ |
| `illustration` | 混合 | 部分 |
| **`vector`** | **PNG** | **多数真透明，但不是保证——见下方踩坑记录** |

去背剪影浮在满版深色底上，是这套主题里最省事也最好看的组合 —— 不用加相框、
不用抠图。所以**深色主题优先 `--type vector`**。

**但 `vector` 不保证真透明**：搜 `paint brush stroke scribble` 这类"笔刷/
纹理描边"素材时踩过一次——拿到的 PNG 看着背景透明（联系表上跟深色底融为
一体），实际是纯色深底直接合成进了像素，每个像素的 alpha 都是 255。
`fetch_images.py` 的可见亮度检测是基于"图本身有真 alpha 通道"这个假设的，
遇到这种"假透明"完全测不出来。图标类素材（人物、物件剪影）目前实测都是真
透明，风险集中在**纹理/笔刷类**素材上——用作 CSS 背景蒙版之前，先抽样查
几个像素：

```python
from PIL import Image
im = Image.open('候选.png').convert('RGBA')
print(im.getpixel((10, 10)), im.getpixel((im.width//2, im.height//2)))
```

如果 alpha 恒为 255，就不能直接当透明图层用——按亮度阈值重新抠图，
做法见 `style-extraction.md`「标题底纹：手绘笔刷用真实素材」一节。

代价：vector 图最大约 1280px。`--min-width` 要相应调到 700-900，
调到 1600 会直接搜不到结果。`size=xl`（560px 显示 × dpr 2 = 1120px）仍然够用，
只有 `hero` 通栏会略欠。
