# 从样图提取风格

## 这是一个循环，不是一张清单

清单会过期 —— 针对某一类样图总结的"必调三件套"，换一张风格语言不同的图就失效。
循环不会：**量 → 判断 → 建 → 再量 → 收敛**，对任何样图都成立。

```
样图
 │  python scripts/style_probe.py sample.png
 ▼
客观数据：主色 + 占比、平均亮度、明暗对比、饱和分布
 │  ← 我在这一步做判断：哪个是背景、哪个是墨色、哪些是并列的分类色
 ▼
assets/themes/<slug>.json          token
 │  ← token 表达不了的结构性特征写进 <slug>.custom.css
 ▼
python scripts/build_theme.py assets/themes/<slug>.json
python scripts/preview_theme.py <slug> -o preview
 │
 ▼
python scripts/style_probe.py sample.png preview/preview-<slug>-card.png
 │  ← 数字告诉我差在哪个维度，不用靠"我觉得不太像"
 ▼
改 token / 改 custom.css → 回到 build_theme，直到收敛
```

**分工原则：机器测量，我判断。**
脚本能精确取色，但分不清一个颜色是"背景"还是"一个分类项"；
我能判断风格气质，但说不准背景到底是 `#171F30` 还是 `#1A2033`。
把判断写死进代码，换一张参考图就失效 —— 所以代码里只有测量，没有判断。

## 第二步：判断 —— 把主色分派到 token

这一步没有脚本能代劳。判断依据：

| 观察 | 结论 |
|---|---|
| 占比最大、饱和度低 | → `bg_card` / `bg_cover`（背景） |
| 与背景明暗相反、占比中等、饱和低 | → `ink`（正文墨色）或 `surface`（面板底） |
| 高饱和、占比小、**只有一个** | → `accent`（单强调色） |
| 高饱和、占比相近、**彼此并列** | → `palette`（分类配色，全部取） |
| 接近纯白/纯黑、占比中等 | → `surface`（面板底）或 `cover_surface` |

**「高饱和色块占比」是最关键的一个数**：

- 低于 ~15% → 单强调色，填 `accent` 就够
- 高于 ~30% → 几乎必然是分类配色，把并列的色全填进 `palette`

**但这个阈值有两类已知盲区，都出现过：**

| 盲区 | 为什么漏 | 实例 |
|---|---|---|
| **小面积分类** | 彩色只用在药丸、小徽章上，面积压不上去 | 手绘信息图，报 7.7% 却是四色分栏 |
| **粉彩分类** | 粉彩天然低饱和，这个指标根本抓不到 | 分层色带榜单，报 5.2% 却有七条色带 |

**指标只能提示，不能判定。** 最终看关系：几个色是**并列**（各代表一个分类项）
还是**主次**（一个跳色 + 中性色）。并列就是分类配色，跟面积和饱和度都无关。

> 这个信号曾经被漏掉过。当时凭印象只提取了一个亮黄 `accent`，
> 而探针会直接报出 43% —— 四栏各一色。
> **数字不会替我判断，但会让我不至于漏看。**

### 判断的是关系，不是色值

问自己一句：这几个颜色之间是**并列**还是**主次**？

- 并列（4个指标、3种人群、5个步骤各一色）→ 分类配色
- 主次（一个跳色 + 一堆中性色）→ 单强调色

颜色的**含义**决定它进哪个 token，跟它好不好看无关。

### 其余轴

背景是纯色还是渐变、字形属于哪一类（黑体/宋体/圆体/手写/等宽）、
圆角量级（0 / 8-12 / 20-28 / 40+）、边框有无粗细、阴影硬度（无/柔和/硬投影）、
留白密度 —— 这些看图直接填，`params.md` 有完整字段表。

只有 5 个必填：`label` / `bg_card` / `title_gradient` / `ink` / `accent`，
其余留空自动推导。**先只填必填项跑一轮**，看差在哪再补，比一次填满快。

---

## 第三步：token 表达不了的，写进 custom.css

`assets/themes/<slug>.custom.css` 会自动追加在生成的主题 CSS 之后，可以覆盖任何规则。

**这是逃生舱，也是这套方案能应对新参考图的根本原因。**

token schema 是一组固定槽位，只能表达我预先想到的风格轴。
新参考图只要有一个我没设槽位的特征 —— 票根缺口、手写下划线、斜切色带、
标题描边、纸纹叠加、非对称圆角 —— token 就表达不了。
而不断给 schema 加槽位是条没有尽头的路，永远慢参考图一步。

逃生舱把这条路封死：**凡是 CSS 能表达的，直接写，不需要先改 schema。**

```css
/* dark-gold.custom.css */
.card-content h1 {
  padding-left: 24px;
  border-left: 10px solid var(--c-accent, #FFD34E);
}
```

取色用 `var(--c-accent)` 之类的变量而不是写死，这样分类配色仍能穿透进来。

判断标准很简单：**试着用 token 表达，两分钟内找不到对应字段就写 custom.css。**
不要为了"用上 token"而扭曲设计。

## 第四步：再量，看差在哪

```bash
python scripts/preview_theme.py <slug> -o preview
python scripts/style_probe.py sample.png preview/preview-<slug>-card.png
```

```
  平均亮度         112.2 →    81.5  (  -30.8)  ⚠️  整体明暗走向
  明暗对比          80.3 →    73.5  (   -6.8)  ✅  层次是否够
  暗部占比          65.0 →    77.6  (  +12.5)  ⚠️  深底还是浅底
  平均饱和          43.9 →    52.2  (   +8.3)  ⚠️  颜色浓淡
  高饱和占比         43.0 →    34.1  (   -8.9)  ⚠️  色块用量
  色板距离          13.3                        ✅  样图主色能否在预览里找到
```

对应处理：

| 指标偏差 | 改哪里 |
|---|---|
| 平均亮度差大 | `bg_card` / `ink` 的明暗走向取错了 |
| 明暗对比偏低 | 拉开 `ink` 与 `surface` 的差；或 `fs_h1` 太小 |
| 高饱和占比偏低 | `palette` 没填，或版式没加 `.palette` —— 多半是**版式**问题不是配色问题 |
| 高饱和占比偏高 | 强调色用得太滥，收敛 `accent_2` / `tag_ink` |
| 色板距离大 | 主色取错，回第一步 |

**指标是信号不是判决。** 数字全绿但观感不对，以观感为准 —— 探针量不出字形气质、
版式节奏、留白呼吸感这些真正决定"像不像"的东西。

## 第五步：收敛判据

预览与样图并排，逐条确认：

- [ ] 眯眼看，两张图的**明暗分布**是否一致（比配色准不准更重要）
- [ ] 颜色的**用法**是否一致 —— 样图用色块填充，我是不是只用了文字色
- [ ] 圆角、边框、阴影属于**同一套逻辑**（硬边+零圆角+硬投影是一组；圆角+柔和阴影+无边框是另一组，混搭必别扭）
- [ ] 中文字形**观感**接近（不必同一款字体）
- [ ] 换一张内容完全不同的卡片再看 —— **风格不应依赖特定内容长度**

---

## 不要提取的东西

| 提取 ✅ | 不提取 ❌ |
|---|---|
| 背景、墨色、强调色/分类色 | 样图的**文案内容** |
| 字形分类与字重量级 | 样图的**装饰插画本身** |
| 圆角 / 边框 / 阴影 / 留白密度 | logo、水印、头像 |
| 结构性视觉特征（写进 custom.css） | 样图的**版式**（几栏、图放哪） |

版式属于 layout，由内容结构决定，见 `layout-authoring.md`。
**把样图的版式复刻进主题，等于把主题绑死在那一种内容结构上，换一篇内容就崩。**

但要**看**版式 —— 样图之所以比默认输出好看，多半赢在版式而不是配色。
看到它用了四栏、编号圆徽、分区标签，就在写 `content.md` 时用对应组件搭出来。

## 背景纹理：真实素材优先于 CSS 模拟

样图如果是纸张/织物/磨砂这类**真实材质**背景，别用渐变凑数。

第一版给 `kraft-marker` 做牛皮纸底时，用了叠加径向渐变模拟纤维颗粒感——
省事、零依赖，但跟真实素材一比，色板距离和观感都明显更差，
**没有纤维颗粒感这件事，CSS 渐变永远做不出来**。

用户提供真实素材（或样图目录里本来就带着背景图）时，直接用：

```python
from PIL import Image
import base64, io

src = Image.open('样图目录/background.png').convert('RGB')
# 按画布 3:4 裁剪缩小——没必要留着原图分辨率，纹理图不需要无损
tw, th = 1080, 1440
sw, sh = src.size
scale = max(tw/sw, th/sh)
resized = src.resize((round(sw*scale), round(sh*scale)), Image.LANCZOS)
# 居中裁到目标尺寸，压 JPEG（纹理图允许有损，体积能压掉 95%+）
...
buf = io.BytesIO(); resized.crop(...).save(buf, format='JPEG', quality=78)
b64 = base64.b64encode(buf.getvalue()).decode('ascii')
```

生成的 `data:image/jpeg;base64,...` 直接写进 token 的 `bg_card`/`bg_cover`——
这两个字段本来就是原样塞进 CSS `background:` 的裸字符串，写完整的
`url('...') center/cover no-repeat` 没有问题，不需要改渲染器。

**为什么内嵌而不是引用本地路径**：渲染时 HTML 写到临时目录，相对路径和
`file://` 绝对路径都脆弱（换机器、换目录就断）。内嵌成 base64 后，生成的
`assets/themes/<slug>.css` 是完全自包含的静态文件，走到哪都能渲染。

## 字体：渲染比对，不要猜名字

`font_title` / `font_body` 会被直接注进 CSS 的 `font-family:`，写**字体族名**，
不要写 `local()`（那是 `@font-face src` 的语法，放这里无效）。

查本机已装字体的族名：

```bash
system_profiler SPFontsDataType | grep "Family:" | sort -u
```

## 标题底纹：手绘笔刷用真实素材，别用 border-radius 凑形状

样图里"标题背后一条马克笔/荧光笔扫过"这种底纹，第一直觉是用纯色块 +
不规则 `border-radius`（撕纸角那种写法）模拟——**这跟"背景纹理用 CSS 渐变
模拟纸张"是同一个错误模式，只是换了个地方犯**。纯色块的边缘永远是几何的，
样图里真实笔刷划过的边缘是毛糙、不规则、深浅不均的，肉眼一眼能看出"这是
拼出来的形状"还是"这是真的笔触"。

正确做法是去图库搜一张真实的粗糙笔刷描边（关键词 `paint brush stroke
scribble`，选边缘毛糙、纯色填充、独立的一条或几条笔触，不要选带手/笔本体
的图），当**形状蒙版**用，而不是当成品配色用：

```python
from PIL import Image

src = Image.open('候选素材.png').convert('RGBA')
crop = src.crop((...))  # 裁出单条笔触
w, h = crop.size
px = crop.load()
out = Image.new('RGBA', (w, h), (0, 0, 0, 0))
opx = out.load()
for y in range(h):
    for x in range(w):
        R, G, B, A = px[x, y]
        luma = 0.299*R + 0.587*G + 0.114*B
        # 亮色是笔触本体、暗色是背景——按亮度算透明度，不要直接信 A 通道
        a = max(0, min(255, int((luma - 15) / (180 - 15) * 255)))
        opx[x, y] = (0xF5, 0xC5, 0x18, a)  # 目标色，自己按主题强调色改
out = out.crop(out.getbbox())
```

**为什么按亮度算透明度，不直接用源图的 alpha 通道**：图库素材经常"看着像
透明背景"，实际是纯色深底直接合成进了像素——每个像素的 alpha 都是 255，
用 `Image.new('RGBA', ...)` 复制过去会整块变成实心矩形，一点笔触感都没有。
先抽样查几个像素的 `(R,G,B,A)`，如果 A 恒为 255 而 RGB 有明显的"亮/暗"两级
分布，就是这种情况，按亮度阈值重新抠图。

拿到蒙版后跟纹理背景一样 base64 内嵌，放在 `::before` 伪元素的
`background-image`，`background-size: 100% 100%` 铺满，不再需要
`border-radius` 凑形状——笔触自带的毛糙边缘就是形状。需要橙/黄两种配色时，
按上面的脚本用不同目标色跑两遍，不要用 CSS `filter: hue-rotate()` 蒙混过去
（色相旋转对这种大面积纯色蒙版会跑偏，跟目标色对不上）。

## 标题描边（贴纸感）：`-webkit-text-stroke` + `paint-order`

手绘/marker/贴纸类风格的标题常见一圈跟字色反差的细描边（黑字配浅色描边，
或反过来），让文字有"贴纸"的立体感，不是简单的纯色平涂。CSS 实现：

```css
.card-content h1,
.card-content h2 {
  -webkit-text-stroke: 6px #F3EAD8;  /* 描边色，通常用页面底色或对比色 */
  paint-order: stroke fill;          /* 先画描边、后画填充，填充盖住描边内侧 */
}
```

`-webkit-text-stroke` 默认以字形轮廓为中心线向两侧扩展，`paint-order:
stroke fill` 让后画的填充盖住描边内侧的一半，只留外侧一圈可见——不加这行，
粗描边会把笔画整体撑粗、糊成一团。

**描边宽度在缩略图尺寸下几乎看不出效果**，是这类细节最容易被误判"没生效"
的地方——验证时要把成品截图裁出标题局部再放大看，见 `qa-checklist.md`
"细节效果"一节。

---

## 标签类小组件的字体要跟标题统一

`.tag`/`.sticker`/`.icon-tile .cap` 这类标签、贴纸组件，如果没有显式设
`font-family`，会默认继承正文字体（通常是系统黑体），而标题多半用的是
单独选的展示字体——同一张卡里，粗体展示字标题旁边站着细体系统黑体标签，
对比会很扎眼，尤其是标题字体本身个性强（手绘/marker 类）时更明显。

建主题的 custom.css 里，给这些标签组件也显式设成跟标题一样的
`font-family`（直接写字体族名字符串，跟 `font_title` 里的值保持一致）。
样图里的标签文字视觉上通常也确实是跟标题同一套字，不是巧合。

## 附：常见情形速查

不是规则，是几类样图各自容易踩的点。**先跑探针，再对照这里**，
不要反过来拿这张表当清单套。

**满版样图**（整张一个底色，没有内嵌面板）—— 探针特征：主色里没有明显的"面板底色"层

```json
"surface": "transparent", "cover_surface": "transparent", "content_align": "center"
```

否则会多出一圈"套娃"色块，内容顶对齐还会在下方留大片空。

**密排大字样图** —— 探针特征：明暗对比高、暗部/亮部占比接近

默认字号量级（正文 42px）偏保守，调到 `fs_body: 48, fs_h1: 84` 一档。
改完必跑 `--dry-run`，放大字号最容易顶溢出。

**分类配色样图** —— 探针特征：高饱和占比 > 30%

`palette` 填全，版式里加 `.palette` 或 `.palette-solid`。
从样图取的是**色块填充色**，渲染器会自动生成提亮版供文字用，
token 里填你看到的原色即可，不要自己先调亮。

**深色主题正文糊** —— `ink` 取浅色时面板底会推成近黑，若 `bg_card` 也深就糊成一片。
让 `bg_card` 和 `surface` 拉开明度差。

**页码**不是风格问题 —— 用 `--no-page-number` 关，不要用 `page_number_color: transparent` 藏。
